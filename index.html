Prior authorization metrics for one clinic

Synthetic data for Lakeshore Specialty Clinic. This is not a Develop Health product.

Problem

Prior authorization sits between a prescription and the medicine. A clinic can trust the numbers only when approval rate, time to a decision, and a stuck case each have one definition.

Solution

This demo turns messy case events into one case spine with dbt, then publishes the metrics from that spine. An agent may answer only from the semantic layer, and each clinic sees only its own rows. Tests lock the grain, the clocks, and the bridge rules.

How it's built

In Snowflake the clinic filter is a row access policy. This demo applies the same predicate in the clinic mart and in every clinic question.

where is_qa_fixture = 0
  and clinic_id = 'clinic_lakeshore'

The Snowflake policy is in dbt/analyses/snowflake_row_access_policies.sql.
